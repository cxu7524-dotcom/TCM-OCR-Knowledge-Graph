# 标注指南与一致性说明

> **合成示意数据，用于工程自测，非命题单位样本、非官方评测结果。**
> 本阶段 GT 全部由 `tools/make_synthetic_pages.py` **机器生成**，并做了机器自检；
> **尚无第三方人工抽检**，人工抽检为待办项，不得在报告中声称已人工标注。

## 一、适用范围

| 数据集 | GT 来源 | 是否人工标注 | 是否计入官方评测 |
|---|---|---|---|
| `SYN-2026-001` 合成示意集 | 脚本渲染页面时同步产出 | 否（机器生成 + 机器自检） | **否** |

## 二、双人独立标注流程（命题样本到位后执行）

1. **分工**：每页由标注人 A、B 独立转写与标注，互不参考；转写以扫描页影像为准，OCR 结果只作参考，不得直接采信。
2. **字段**：逐块记录 `page_id / bbox / line_id / quote / source_hash`，实体与关系记录 `type / name / value / head / relation / tail`，字段口径见 `README.md`。
3. **裁决**：A、B 不一致项交由第三人 C 裁决，记录裁决理由与裁决人代号，写入 `裁决记录.jsonl`。
4. **一致性检验**：
   - 实体 / 关系标注计算 Cohen's Kappa，**目标 κ ≥ 0.80**；低于阈值须重训标注人并重标该批。
   - 每批次**人工抽检比例 ≥ 20%**（且不少于 5 页），抽检人不得是该页的原标注人。
   - 抽检结果登记：抽检页数、不一致条数、修正条数、最终 GT 版本号。
5. **版本与变更日志**：GT 版本由 `eval/dataset.py:version_hash()` 由六类文件内容计算；每次修改在 `数据集版本.md` 追加变更原因、影响页、修改人、日期。评测报告必须注明所用 GT 版本哈希。
6. **保密**：命题单位样本的影像与人工标注放 `data/annotation/official/`（已列入 `.gitignore`），不进仓库、不上传任何外部服务；赛后按约定删除 / 归还。

## 四、GT 与预测的对齐口径（正式规范）

### 4.1 对齐键统一归一化

- 字段对齐键为 `(page_id, type, name, value)`，**唯一实现**是 `app/schemas.py:entity_align_key()`；
  `eval/dataset.py:align_key()` 与 `extract/evaluate.py:align_key()` 都只是它的委托包装，禁止另写一份。
- 归一化函数 `app/schemas.py:align_norm()` 的顺序固定为：
  **去空白与常见标点（`norm_for_match`）→ 异体字表映射 → 繁简映射**。
- **对称性要求（强制）**：GT 与预测必须走同一个函数。**禁止只归一化预测、不归一化 GT**，
  那是作弊，不是口径修正。
- 归一化只影响「两个字段是否判为等价」，**不修改任何落盘数据**。

### 4.2 原文保留规则

- GT 文件里的 `quote`、`name` 等**原文一律保留繁体 / 异体字形**，一字不改。
- `quote` 必须与对应 `Block.text` 一致，不得为了对齐而改写、简写或补字。
- 预测侧同样保留 OCR 原文；`Block.text_norm` 只是附加字段，不替换 `text`。

### 4.3 为什么这是口径修正，不是放宽标准

- 修正前的问题：GT 的 `name` 保留繁体（如「芍藥」），而预测基于归一化文本输出简体（「芍药」），
  两者被判为不等 → **抽对了也算错**（假阴性）。这是判定缺陷，不是模型能力差距。
- 修正后：两侧都做同样的字形归一化，「芍藥」与「芍药」视为同一字段；
  但**字段类型、页归属、取值本身仍然必须一致**，没有任何阈值或匹配条件被放宽。
- 报告必须**双列披露**：修正前（原值对齐）与修正后（归一化对齐）两个数并列，
  并注明「差异来自字形等价判定，非模型能力提升」。修正后若仍低于阈值，如实写未达标。

### 4.4 计分与排除

- 按 `page_id` 哈希切分训练 / 测试页（种子 2026，测试 30%），默认只在测试页计分；同页不跨集合。
- `is_demo=True` 或缺溯源字段的记录由 `clean_records()` 与五个 `compute_*` 双重排除，报告列出排除条数。
- 每份报告必须注明 GT 版本哈希（`eval/dataset.py:version_hash()`）。

## 五、字段粒度规范（P2，与抽取规则同口径）

粒度不一致会直接制造假 FP（预测片段 vs GT 整句），因此按字段固定粒度：

| 字段 | 粒度 | 示例 | 说明 |
|---|---|---|---|
| 主治 | **整句 / 短语**（以「主 / 主治」引导，到空格或句读为止） | `五脏六腑寒热邪气` | 不拆成「寒热」「邪气」多个实体 |
| 功效 | **一个主功效词** | `利小便`、`补血` | 一行有多个功效时，GT 只标主功效，规则取最长命中 |
| 性味 | **一个完整性味词** | `味甘平`、`味辛温` | 不拆成「味甘」+「平」；长词优先于短词 |
| 归经 | **经络名** | `脾经`、`肺经` | 不带「入」「归」等引导词 |
| 剂量 | **数值 + 单位**（炮制另记） | `三两`、`十二枚` | 不含炮制词（炙 / 切 / 擘） |
| 药材 / 方剂 | **正名**（不含炮制前缀） | `甘草`、`桂枝汤` | 「炙甘草」记 `甘草` + 炮制属性 |

规则侧 `extract/rules.py` 按同一粒度切分：性味/功效取最长命中，剂量要求「药名 + 剂量」共现。

**本阶段统计（测试页）**：FP 24 条中粒度类 7 条（29.2%），其中多数源于 OCR 漏字
（`五脏六腑寒热邪` 缺「气」、`逆上气` 缺「咳」），**不是规则切分粒度问题**；
剩余 FP 多为 GT 覆盖不全（如「温中下气」未被标注）。因此本阶段**不改 GT**，
只记录结论，粒度规范供下一轮标注与规则同步使用。
