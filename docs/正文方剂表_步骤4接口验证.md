# 步骤 4：上传、存储与页面接口核验

## 实现

普通上传 `_ingest` 在既有 OCR 和图谱抽取之外调用步骤 2、3 的正文候选与药量抽取，并将结果随页保存到 JSON 快照和 SQLite `formula_extractions`。此表按 `page_id` 整体覆盖；删除页面时一并清理。SQLite 保存原书表格结构作为快照缺失时的恢复依据。JSON 快照不可读／缺失时，页面接口从 SQLite 恢复已保存的正文结果、表格及 OCR 块。历史快照没有正文结果字段时，接口标 `formula_extraction_status=legacy_missing`，保持原有表格缺字段行为，不伪造新结果。

上传响应和 `GET /api/pages/{page_id}/ocr` 共用 `_tables_payload`：原 OCR 规整表标 `source_type=原书表格`；正文方剂每方一表，标 `正文抽取`，复用 `rows`、单值 `cell_refs`，并增加同形 `cell_refs_multi`、`cell_statuses`、`cell_ref_scopes`、`field_details`、`continuation`。待核或原文未载没有直接剂量文字时，引用配伍上下文并用 `cell_ref_scopes=配伍上下文` 明示，而不冒充精确剂量来源；实际字符范围、缺载依据仍在 `field_details`。页首续方提示在 `formula_continuation_hints` 单独返回。

去重只在每味药名和剂量分别有完整的、与原书表格单元格相同的 OCR 块引用和文本，且每行均可核对时抑制正文重复；无法证实同出处就保留。同名但出处不同的正文方剂有不同 ID。ID 根据页面和起方／配伍的块及字符范围稳定生成，不靠方名去重。

`python -m unittest discover -s tests -q`：179 项通过。其中新增的 `tests/test_formula_api.py` 覆盖跨块多引用、可核查上下文、旧字段兼容、同名不同出处、完整同出处去重及重复构造稳定。全量测试中未运行固定验收页的真实识别验收。

## 剩余限制

本步只接入接口与存储，现有页面尚未实现新类型的专门展示和多引用点击，留给后续步骤。真实 OCR、配伍切段和原表还原均可能出错；混合图接口返回的表格形状已显示现有版面聚类的实际问题。正文去重有意严格，难以确认同出处时可能保留重复项；未声称同名即同方。历史无正文结果的页需要重新上传才能得到入库的正文结果。
