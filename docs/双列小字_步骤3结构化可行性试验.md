# 步骤 3：字符字团结构化可行性试验

结论：当前试验**没有开发集净收益**，因此没有冻结第六版，也没有对固定八页进行第六轮推理。第五轮既有结果保持 11/20 正例完全正确、1/22 负例误拆；原 20 正、22 负分母和 ≥18/20、≤5% 门槛均不变。以前五轮记录均未覆盖。

## 结构化方法及范围

新试验不修改生产流程。以既有自动父列和几何候选为种子，提取不同对比度的连通墨迹组；对两个纵向尺度计算左右墨量平衡、位置、字团跨中缝情况及墨迹强度，使用三状态动态规划在背景、主字和双轨之间整体分配，偏好状态纵向连续和主字后接双轨。当前打分使用对比度 22 的字团及两个窗口尺度；对比度 14、30 的字团也有记录，但尚未参与状态打分。子列分别由状态区域中的左右字团确定，主字使用相邻的前一主字状态。它仍以 v3 几何候选为种子，**不能发现 v3 没有提出的目标**；这是本次可行性试验的重要限制。

开发样本和自动父列沿用第 32、33、35、36、38、42 页的开发对照，另含第 31 页和第 35 页误挂正文反例。标注只用于选择要检查的自动父列及推理后的比较；没有把目标框输入状态模型，也没有用固定八页训练或逐例写规则。以第五轮连通字团候选为基线，图像高对比墨迹覆盖只作为辅助指标，不能替代逐图检查。

以下仅在第五轮已评测结果上查看无叠框原图，不用于修改规则或降低门槛。`previous_failures_raw_context.png` 保存了对应原图局部；物理字轨、语义分组与裁框评价应分别记录。

- P46-06：半夏下可见左右各一个小字，薑／製属于两条物理短轨；原始识别为空与顶部裁字是不同问题。
- P46-08：麻黃下可见两条小字轨；右侧“八分若頭不”和左侧“疼無汗不用”在语义上可能接成连续说明，不能仅因句子连续而取消物理双轨标注。
- P50-09：黃芩下的右侧剂量及左侧酒炒分别有可见的小字轨；主字底端的裁切仍按原判。
- P34-10：大膠棗下有右侧“十枚煮”和左侧“去皮核”两轨；处理说明的语义顺序需要结合上下文，不能从单张局部图推断为不存在双轨。
- P49-13：親切下的左右两条细字均有实印，呈较长的并列说明；本次没有重新检测该固定页。

- P45-19：右“方見”、左“中風”两轨可见；页脚紧邻版框，完整索引语义需要上下文，原有中缝裁字判定不变。
- P49-20：右“方見中”、左“暑門”是两条物理小字轨，同时合成跨轨索引词；原错误关联已回退但目标漏拆，保留原判。

## 数据与本机能力

现有独立开发标注仅 7 个正例和 4 个负例，固定组 42 例已经反复使用。它们足以暴露本次退化，不足以可靠训练并验证泛化的局部学习式检测器，尤其不能再将固定组当作新鲜盲测。需要在其他页面、最好不同版刻或书籍上补充：单字短轨与两轨不等长；顶部贴主字及末尾紧邻后续大字；跨轨连续说明和索引；透印、淡墨、残损、页框及普通大字的难负例。每例应记录自动父列、字团或字符框、物理轨道、前一主字关联、阅读顺序、实印与透印、疑难语义及审阅分歧，并按页面或书籍划分训练、开发和未看验收集。

当前环境有 NumPy、OpenCV 图像处理、ONNX Runtime 和 RapidOCR；可继续运行自定义 NumPy 动态规划、使用已安装模型推理、提取图像特征和离线做小规模实验。当前环境未发现 PyTorch、scikit-learn、SciPy；本机 OpenCV 5.0.0 也没有暴露 `cv2.ml`。因此不应声称可用现有环境直接进行这些框架的模型训练，现有 ONNX Runtime 主要提供已存在模型的推理。

建议下一步先补充独立标注，再将状态改为允许“左、右各自持续或结束”的联合状态，并针对短轨、长轨、普通大字和透印分别验证；在独立开发集有净收益后才考虑新一次固定集复测。步骤 4 继续等待验收。
