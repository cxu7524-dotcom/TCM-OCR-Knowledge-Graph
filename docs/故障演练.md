# 故障演练与错误态清单

这份文档记录「故意把东西弄坏之后，系统会怎么表现」。目的是两件事：

1. 答辩现场如果哪一步失败了，能立刻判断是环境问题还是系统问题；
2. 证明它不是只能在一切顺利时跑通的演示壳。

自动化部分在 `scripts/faults.py`（13 个负向用例，纯标准库，Windows/Linux 都能跑）：

```bash
python scripts/faults.py --port 8000      # 服务起来后跑
```

全 PASS 退出码 0，任何一条不符合预期退出码 1。

---

## 一、自动化用例实测（2026-11，本机 8000 端口）

| 用例 | 制造方式 | 实测状态 | 实测文案 |
|---|---|---|---|
| 非图片扩展名 | 上传 `note.txt` | 400 | 不支持的格式 .txt：只接受 bmp / jpeg / jpg / png / tif / tiff / webp。 |
| 假图片 | `fake.png` 里塞纯文本 | 400 | 图像无法解码：文件不是有效的图片（常见原因是把别的文件改了扩展名）。 |
| 超限上传 | 21 MB 的 png | 413 | 文件过大：21.0 MB，上限 20 MB（可用 TCM_MAX_UPLOAD_MB 调整）。 |
| 页面不存在 | `GET /api/pages/nope-1234/ocr` | 404 | 未找到该页面，请先在步骤一上传或加载示例数据 |
| 接口不存在 | `GET /api/nothing` | 404 | 接口不存在（404）：检查路径与方法是否写对 |
| 方法不对 | `GET /api/rag/rebuild` | 405 | 这个接口不支持该请求方法（405） |
| 缺字段 | `POST /api/asr` 不带文件 | 422 | 请求参数不完整或格式不对（file） |
| 空消息 | `text=""` | 400 | 说点什么再发 |
| 超长消息 | 700 字 | 400 | 一条最多 600 字 |
| 房间不存在 | 往 `nope` 发消息 | 400 | 聊天室不存在 |
| 空提问（聊天室 AI） | `question=""` | 400 | 先写一句要问的 |
| 空问题（问答接口） | `question=""` | 200 | 问题为空，原文未检索到依据。仅供参考、非诊疗建议 —— 按约定拒答，不是报错 |
| 发言限流 | 同一人 1.2 秒内连发两条 | 429 | 说得太快了，歇 1.2 秒再发 |

结论：**没有一条走到 500，也没有一条把失败当成功**；框架层的英文默认文案（`Not Found` / `Method Not Allowed` / `Field required`）已经全部翻成中文。

## 二、需要环境才能制造的故障（实测记录）

### 2.1 本机大模型没起（最可能发生）

制造方式：另起一个实例，把模型地址指到死端口——

```powershell
$env:TCM_LLM_BASE_URL="http://127.0.0.1:9/v1"; $env:TCM_LLM_TIMEOUT="8"
.venv\Scripts\python.exe app\main.py --port 8124
```

实测结果（问「甘草的性味是什么？」）：

- `/api/rag/status` 仍报 `llm.enabled=true`（配置层面确实开着）；
- `/api/qa` 返回 **200**，用时 **4.7 秒**（不是超时挂死），`refused=false`；
- 答案降级为原文摘录：「原文中与…相关的记载：[1]「甘草 味甘平 无毒」（DEMO-001 / L02）…仅供参考、非诊疗建议。以上为原文摘录，未做推断。」
- 证据照常带 bbox；`qa/rag.py` 有专门的降级分支 `_extractive_fallback`（模型不可用时只列原文、不编造），实测这次答案的收尾是「以上为原文摘录，未做推断」。

也就是说：**模型挂了，问答不挂**，只是从「解释」退到「摘录」。`/home` 页另有独立指示：`/api/llm` 返回 `ready=false` 时，右上角胶囊显示「AI 助手未就绪」，悬停给出原因。

### 2.2 语义索引缺失或过期

`qa/rag.py` 在索引不可用时把 `meta["note"]` 置为「语义索引不可用，本次未做向量检索」，退回字面锚点检索；`/api/rag/status` 的 `index.stale=true` 与 `index.health` 会如实反映。
`data/store/vectors/` 未入库，评委 clone 后不重建索引就是这个状态——功能可用，只是没有向量召回。重建见[复现说明](复现说明.md)第四节。

### 2.3 OCR 依赖缺失

`rapidocr-onnxruntime` 没装时，`/api/pages` 返回 **503**：「OCR 依赖不可用：未检测到 rapidocr-onnxruntime。请先 pip install -r requirements.txt，再重启服务。」并带诊断串。
认不出真实文字时返回 503 且**不返回示例数据冒充实测**（`OCR 未能完成真实识别…本次不上传、不返回示例数据`）。

### 2.4 语音模型缺失

`/api/asr/status` 返回 `ready=false`，界面如实显示语音入口不可用，浏览器语音通道仍可用；录音超 25 MB 返回 413，空音频返回 400。

### 2.5 后端没起 / 端口被占

- 三页都请求 `/api/health`，失败时页头显示「服务未就绪」并 toast「后端未就绪：…」，不是白屏；
- 端口占用：`scripts/start.ps1` 依次试 8100 / 8000 / 8101-8103 并打印 `[note] 8100 已被占用，改用 8000`。

## 三、这次为了「可读」改了哪些地方

1. `app/main.py` 新增两个异常处理器：
   - `RequestValidationError` → 422 统一为「请求参数不完整或格式不对（字段名）」，附 `errors` 计数；
   - `StarletteHTTPException` → 仅对 `/api/*` 改写英文默认文案（404 接口不存在 / 405 方法不支持），页面与静态文件不受影响。
2. 三页 `errText()` 补齐分支：演示台加 422 / 429，问答页加 404 / 422 / 429，并把 413 / 503 的前缀去掉——原来会出现「文件过大（413）：文件过大：21.0 MB…」这种重复。

## 四、已知不一致（留档，暂不改）

聊天室里「房间不存在」在不同接口上返回码不一致：`/api/chat/messages`、`/api/chat/roles`、`/api/chat/notice` 是 404，`/api/chat/send`、`/api/chat/ask`、`/api/chat/export` 是 400。

原因是前者在接口层直接抛 404，后者经 `except ValueError → 400` 统一兜底。前端只读 `detail` 文案并 toast，用户看到的是同一句「聊天室不存在」，所以没有实际影响。统一成 404 需要引入 `chat_room.NotFound` 并改 20 处 catch，收益低、回归面大，留到有富余时间再做。
