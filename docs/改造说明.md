# 改造说明：A23 智能文档助手 → 赛题二原型（框架搭建阶段）

- 基线：`git tag baseline-a23`（改造前工作区干净，仅 `docs/项目改造提示词.md` 未跟踪）
- 框架提交：见 `git log`，提交信息「框架：A23 → 赛题二 骨架搭建」
- 阶段目标：**只搭框架、打通端到端空跑链路**，不训练模型、不追指标、不编造实测数字
- 回退：`git show baseline-a23:<路径>` 查看旧文件；`git reset --hard baseline-a23` 整体回退（会丢弃框架提交，谨慎）

---

## 一、技术决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | 原地改造，不新建平行项目、不重新 clone | 保留 git 历史与可回退性 |
| 2 | 先打基线 tag，再删除 / 归档 | 所有旧资产可从 tag 完整恢复，删除不丢数据 |
| 3 | 旧资产**只留索引、不保留文件** | 旧材料含合同/投诉/采购等办公文档与废弃业务代码，留在工作区会造成「A23 业务残留」；且部分旧脚本含已废弃的云端与数据库字样，影响「全库无旧依赖残留」验收。完整清单在 `docs/archive/文件清单.txt` |
| 4 | MySQL → SQLite + JSON 镜像 | 零装机门槛；保留 `store.py` 的 quote + 坐标 + run_id 幂等设计，`run_id` 改为由来源指纹确定性生成，重复跑零膨胀 |
| 5 | 数据契约用标准库 dataclass，不用 pydantic | 让 `eval/run_all.py` 等命令行入口在没装 Web 依赖时也能独立跑；FastAPI 层只做 dict 收发 |
| 6 | `Provenance` 基类统一溯源五元组 | Block / Entity / Triple / Evidence 全部继承，字段定义只在 `app/schemas.py` 出现一次；`quote` 缺省回填原文，保证全链路不丢字段 |
| 7 | 云端在线推理调用路径**彻底移除** | 新代码零密钥、不读 Key 文件、不访问公网；`LlmConfig.is_local()` 硬性只允许 127.0.0.1 / localhost |
| 8 | OCR 默认声明 `rapidocr`，依赖缺失自动降级为桩 | 既满足「默认 CPU 可跑的本地 OCR」，又满足「不装可选依赖、不联网、不装 GPU 也能跑通」；降级在 notes / 界面 / 报告中显式标注 |
| 9 | 前端零 CDN、图谱用原生 Canvas 力导向图 | 离线验收要求；不引入 D3/ECharts/Neo4j/ES 等外部组件 |
| 10 | 问答采用「抽取式原文摘录 + 强制证据校验」 | 本阶段不做生成式推断，杜绝模型自由发挥；`quote` 命中原文才放行，否则转拒答 |
| 11 | 评测只给口径，指标一律「待测」 | 无 GT、无真实模型输出时禁止填数字；示例数据被 `is_demo` 显式排除在计分之外 |
| 12 | 新增 `app/demo.py` 作为演示态唯一入口 | 保证「示例数据 / 模型未接入」在界面、接口、报告里文案一致，示例数据也走同一套数据契约 |

## 六、自验结果（对照提示词第 9 节）

| # | 验收项 | 结果 |
|---|---|---|
| 1 | 装依赖后能起服务，不需数据库 / Key / GPU / 联网 | 通过：`pip install -r requirements.txt` → `python app/main.py`，实测 127.0.0.1:8000 正常 |
| 2 | 四步演示台 + 常驻免责 + 示例标注 | 通过：四步页面可串通；「仅供参考、非诊疗建议」与「示例数据 / 模型未接入」常驻 |
| 3 | 无依据问题拒答并说明「原文未检索到依据」 | 通过：`黄芪在本书中用量几何？` → `refused=true`，`refuse_reason=原文未检索到依据` |
| 4 | `python eval/run_all.py` 可重跑，五项指标「待测」 | 通过：报告骨架幂等覆盖生成，五项均为「待测」且列出缺失条件 |
| 5 | 全库无云端 / 旧依赖字样 | **代码与配置通过**；唯一例外是 `docs/项目改造提示词.md` —— 它是用户提供的任务依据文件，正文（第 2 节与验收 5）本身引用了这些历史名词，属文档描述而非调用路径，按要求原样保留 |
| 6 | 目录结构与 README 一致、旧文件去向可查 | 通过：本文件 + `docs/archive/文件清单.txt` |
| 7 | git 有基线 tag 与框架提交 | 通过：`baseline-a23` 已打，框架提交见 `git log` |

端到端实测记录（示例数据）：上传 → 10 个文本块 / 35 实体 / 23 三元组 / 22 节点 23 边 → 问答可答 2 例、拒答 2 例；所有证据带 `page_id / bbox / line_id / quote / source_hash`。

## 七、未完成项与下一步（按优先级）

1. **本地 OCR 接入**：实现 `RapidOcrAdapter.infer()`，映射 bbox / conf，竖排版面检测与列切分，异体字全量表。
2. **古籍样本与人工标注**：命题单位脱敏样本接收登记、逐页转写 GT、实体 / 关系 / 表格结构 GT、无依据问题集。
3. **本地 LLM**：本机 Ollama / vLLM 部署，抽取与生成 prompt + JSON Schema 约束，输出二次 quote 校验。
4. **指标实测**：`eval/metrics.py` 的 compute_* 实现，五项指标出正式报告（当前一律待测）。
5. **交付物**：参赛报告 / PPT / 演示视频 / 复现实验记录。

## 八、已知限制

- 示例页文本为**合成示意文本**，不是真实古籍原文；`data/demo/` 不得进入评测计分。
- 规则抽取的跨行主语归属为启发式（禁忌优先取行内主语），需本地 LLM 与人工标注校验。
- `qa/index.py` 的 hash 向量是占位实现，不是语义向量，不得用于指标实测。
- `docs/赛题二原文.md` 为要点摘录，正式赛题原文待补录。
- 提示词文档作为任务依据保留在 `docs/`，其中的历史依赖名词仅用于描述改造目标。
