# 阶段十一：语义向量检索与 RAG 问答实现说明

> 本阶段把问答从"关键词命中就摘一段原文"升级为完整的检索增强生成（RAG）：
> 语义向量检索 → 双阈值 + 字面锚点 → 专业提示词 → 本机大模型生成 →
> 引用回映射到「书名 / 页 / 行 / bbox」。

## 1. 为什么改

改造前的问答有两个硬伤：

1. **答非所问**：字面检索靠二元组重合打分，用户问「甘草有什么功效」，原文写「甘草味甘平，无毒」，
   字面命中后系统只把原文摘出来，读者仍然不知道"功效"是什么。
2. **检索不到就拒答**：只要没有高分段落，系统就回「原文未检索到依据」，
   导致大量本可以正常回答的问题被挡掉。

赛事评分里「问答可溯源 15 分」看的是"答案有出处"，而不是"答案必须是原文摘录"；
「无依据正确拒答 10 分」看的是"没有依据时要说不"。两者并不冲突——
**有依据就给依据，没依据就说清楚没依据**，而不是一刀切拒答。

## 2. 整体链路

```text
                     ┌──────────────────────────────────────┐
用户问题 ──► 越界判定 │ 个人诊疗 / 剂量 / 疗效 → 直接拒答      │
                     └──────────────────────────────────────┘
                              │ 通过
                              ▼
              查询扩展：现代词 → 古籍用词（失眠→不寐/不得眠…）
                              │
                              ▼
              语义向量编码（bge-small-zh-v1.5，512 维，L2 归一化）
                              │
                              ▼
              全库余弦检索（numpy 矩阵乘，top-k×3 候选）
                              │
                              ▼
   双阈值：score ≥ 0.49 且 score ≥ top1 × 0.72
                              │
                              ▼
   字面锚点：与原文至少共享 1 个实词二元组（去功能词，古籍等价词也算）
                              │
              ┌───────────────┴────────────────┐
         有命中                          无命中
              │                                │
              ▼                                ▼
   RAG 提示词（原文片段 1..n）      常识提示词（声明无依据）
              │                                │
              └────────────► 本机大模型 ◄──────┘
                              │
                              ▼
        解析 [编号] → 映射 书名/页/行/bbox → Answer.sources
```

## 3. 关键技术选择

### 3.1 向量模型：本地 ONNX，不引入 torch

| 方案 | 结论 |
|---|---|
| sentence-transformers + torch | 依赖约 800MB，与"纯 CPU、轻量、可复现"的工程约束冲突 |
| Ollama embedding（bge-m3） | 1.2GB，本机网络两次在 850MB 附近停滞，且 Ollama 服务默认不开 embedding |
| **本地 ONNX bge-small-zh-v1.5** | **90MB，onnxruntime 已是 OCR 既有依赖，单条编码约 10ms** |

最终方案：`tokenizers`（3MB 的 Rust 扩展）+ `onnxruntime` 跑 BERT 句向量，
取 `[CLS]` 池化后 L2 归一化，余弦相似度退化为点积，检索时一次矩阵乘完成。

模型来源：ModelScope `Xenova/bge-small-zh-v1.5`（Transformers.js 官方 ONNX 分发），
由 `tools/download_embed_model.py` 下载，失败自动断点续传。

### 3.2 段落切分而非按行检索

古籍 OCR 的文本块平均只有 13 个字（一列一行）。直接用单行做向量检索有两个问题：
语义信息不足，且相邻行被切断后模型读不出完整语义。

因此 `qa/kb.py` 把同一页的相邻块按阅读顺序合并成约 160 字的**段落**作为检索单位，
命中段落后再回落到底层文本块，给出精确到行的出处。实测每页约 12.5 个块、约 2.2 个段落。

### 3.3 阈值是实测出来的，不是拍的

在 12 条域内问题 + 8 条域外问题上扫描阈值：

| 阈值 | 域内命中率 | 域外误命中 | F1 |
|---|---|---|---|
| 0.44 | 1.00 | 0.50 | 0.667 |
| 0.46 | 1.00 | 0.38 | 0.769 |
| 0.48 | 1.00 | 0.25 | 0.857 |
| **0.49** | **1.00** | **0.12** | **0.933** |
| 0.50 | 0.83 | 0.12 | 0.854 |
| 0.56 | 0.75 | 0.00 | 0.857 |

取 0.49（`TCM_RAG_MIN_SCORE`）。此时仍有 1 条域外问题（"帮我写一首关于春天的诗"，0.553）
越线，原因是诗歌类文本与古文在字符分布上确实接近——这靠余弦相似度无法解决，
因此再加一道**字面锚点**：查询与原文必须至少共享一个实词二元组（剔除"什么/怎么/可以/帮我"等功能词）。
该问题与任何古籍段落都没有实词重合，被正确剔除。

### 3.4 查询扩展：现代词 ↔ 古籍用词

古籍里几乎不出现"失眠""腹泻""便秘"这类现代说法，直接拿现代词做向量检索会平白丢召回。
`qa/rag.py` 内置约 30 组映射（失眠→不寐/不得眠/目不瞑，腹泻→泄泻/下利/溏泄，
便秘→大便不通/燥结，怀孕→妊娠/胎前 …），命中后把等价词拼进检索串一起编码，
并允许这些等价词充当"字面锚点"，避免扩展召回的段落又被锚点校验误杀。

效果（同一批问题，扩展前后）：

| 问题 | 扩展前 | 扩展后 |
|---|---|---|
| 失眠在古籍里怎么解释 | 无依据 → 常识作答 | 命中 1 段 0.58，给出「阳明经表病…不得眠」并标注出处 |
| 腹泻用什么方 | 无依据 | 命中 2 段 0.66 |
| 便秘怎么治 | 无依据 | 命中 2 段 0.64，引到三化汤、备急丸 |

### 3.5 提示词：把"依据"和"常识"分层

生成提示词要求模型：

- 先给结论再解释，不用「根据您提供的资料」这类套话；
- 有原文依据的句子标 `[编号]`；
- 原文不足时可用常识补充，但必须以「（据中医常识）」开头，且不得标编号；
- 不给个人诊断、处方剂量、疗效承诺；
- 不主动给出用量数字，原文剂量只能原样引用。

无依据时切换到另一套系统提示词：第一句固定写「本古籍库未检索到直接依据。」，
再由模型自律判断"问题是否属于中医 / 健康范畴"——属于则正常解释，
不属于（如"写一首诗"）则先说明本系统定位、再从中医视角给出克制回应，
**不允许把自己的内容说成"中医常识"**；全文禁止出现 `[编号]`。

### 3.6 页面作用域与示例页

检索范围按"是否选定了当前页"自动切换：

- **首页聊天（未选页）**：`scope=library`，全库检索；检索不到 → 声明无依据 + 常识作答；
- **演示台（选定某页提问）**：`scope=page`，只在当前页的段落里检索，出处天然页内可溯源；
  页内检索不到 → 回退原有的页内抽取/拒答链路，**保住"无依据正确拒答"的评测语义**。

另外，内置示例页（DEMO-001）**不进语义知识库**：它是给"加载示例→按页问答"演示用的
教学页，不该在全库检索里抢《温疫方論》们的头号出处。用户自己上传的页面照常入库——
"上传一页 → 全库即可检索该页"是产品特性。

## 4. 可溯源的落点

答案里的 `[n]` 由 `_cited_indexes()` 解析后，按顺序映射到检索命中的段落：

```json
{
  "sources": [
    {
      "index": 1,
      "book": "温疫方論",
      "page_id": "温疫方論__p15",
      "line_id": "L00",
      "line_span": "L00–L06",
      "quote": "温疫论卷之一……",
      "bbox": [40, 0, 984, 73],
      "score": 0.6392,
      "cited": true
    }
  ],
  "retrieval": {
    "mode": "semantic-rag",
    "embed_model": "bge-small-zh-v1.5",
    "hits": 3,
    "top_score": 0.6392,
    "floor": 0.49,
    "answered_without_evidence": false
  }
}
```

`evidences` 仍保留并逐条回原文校验（`quote` 必须能在所属段落原文中命中），
因此"可溯源率"口径没有被削弱。

## 5. 知识库构成

| 来源 | 页数 | 说明 |
|---|---|---|
| ModelScope `AncientDoc` 医家类（转写建库） | 117 | 7 部医书；文本为数据集机器转写，bbox 为按行序推算 |
| ModelScope `AncientDoc` 医家类（**真实 OCR 重建**） | 59 | 评测三部书：丹方彚编 21 + 合併脉訣難經太素評林 16 + 思濟堂方書 22；bbox / 置信度 / 阅读顺序均为真实检测结果 |
| 内置示例页 | 1 | 仅用于"加载示例→按页问答"演示，**不进语义知识库** |
| **合计** | **177 页 / 4100 块 / 392 段** | 索引 392 条 512 维向量 |

导入命令见 README。**诚实性说明**：117 页转写页的 `bbox` 是按阅读顺序推算的行框，
`engine` 记为 `dataset-transcription`，`notes` 写明「无原图，bbox 为按行序推算，
非版面检测结果」；59 页评测子集已从同一 ModelScope 数据集下载原图
（`tools/download_eval_pages.py`）并用生产 OCR 链路原位重建
（`tools/reingest_eval59.py`，page_id 不变），`engine=rapidocr`。

代价要说明白：真实 OCR 的逐列文本有 5% 上下的识别错误、且被切成窄窄的竖列条，
这些页的**段落语义质量比转写页略低**（如"伤寒的传变规律"原来命中《合併脉訣難經太素評林》
4 段 0.66，重建后命中《温疫方論》1 段 0.57）——换来的是出处可点回原图真实位置。
检索阈值 0.49 在两种文本上都成立。

## 7. 已知局限

1. **域外误命中未清零**：诗歌类等文体相近的问题仍可能过阈值，字面锚点能挡住大部分但非全部。
2. **部分页面无真实 bbox**：评测子集 59 页已用原图重跑真实 OCR（bbox 为检测框）；
   其余 117 页仍为转写文本，行框是推算值，点回原图的位置不精确。
3. **实体/关系抽取仍以规则为主**：176 页仅抽出 1098 个实体、314 条三元组，覆盖率偏低，
   图谱问答更适合逐页核对而非全库统计。
4. **7B 模型的中医术语能力有限**：偶尔会把原文的剂量直接复述成"通常用量"，
   提示词已明确禁止，但仍需人工抽查。
5. **索引重建是同步的**：`/api/rag/rebuild` 在大语料下会阻塞，当前规模（399 段）7 秒内可接受。

## 8. 回归保障

- `python -m unittest discover -s tests -t .` → **122/122 通过**；
- `qa/rag.py`、`qa/kb.py`、`qa/index.py` 对旧接口保持向后兼容，
  `TCM_RAG_ENABLED=0` 可一键回退到原字面检索链路；
- `Answer` 新增 `sources` / `retrieval` 为可选字段，`from_dict` 自动忽略未知键，旧调用方无需改动。
