# 双列小字步骤 1：固定局部样本与改动前基线

## 范围

开发：思濟堂方書 page_35 一处白朮，数据见 `output/small_columns_step1_dev/annotation.json`。留出：同书 page_34、37、39、43、45、46、49、50，以整张扫描图及 SHA-256 分组；均不含开发页及其裁图。此留出组供后续双列任务使用，不得用于该任务调参。37、39、50 曾是本仓库另一项方剂表任务的验收页，因此不能声称这些页面从未在本项目曝光。

本数据仅覆盖框定的局部片段，不是整页方剂完整标注或验收。不得据此计算整行准确率、全页召回率，也不代表命题单位样本。

## 样本与证据

`output/small_columns_step1_holdout/annotations.json`：20 正例、22 反例。正例中 11 处双列含可辨剂量，9 处不含双列内剂量，只纳入几何分栏评估；page_45 的二錢属于主文而非双列内剂量。反例为普通大字 18、单列小字 2、透印 1、相邻大字列靠近 1，负例类别分布不均衡。每例坐标按原图像素，双列逐框有转录及读取顺序；共享剂量仅记录一次，并记录可判定的适用药味。page_34 的「大〔?〕棗」字形保留待核，不据药名补字。该批样本已经对原图与叠框检查，尚无第二人独立复核。

逐页正/负：34 3/0；37 1/6；39 3/14；43 3/0；45 3/0；46 3/2；49 3/0；50 1/0。图片证据：`output/small_columns_step1_holdout/positive_overlay.png`（红色右框、绿色左框、蓝色主文框）；更早的 `review_overlay.png` 只覆盖早期候选，最终应以 JSON 为准。扫描原图路径、哈希与尺寸逐页记录在 JSON 中。`output/small_columns_step1_dev/contact/` 保存放大图及坐标网格；它们是辅助证据，原始坐标和图像仍以扫描原图为准。

## 基线口径

在现有工作树代码上使用 `ocr.pipeline.run_ocr` 默认路由及默认识别模型配置，独立导出每页结果。重定向报告目录，避免覆盖原有队列和纠错记录。`page_N_selected_raw.json` 是另一次调用 `_recognize_page` 后、低置信过滤及版面合并前的所选识别块；`page_N_full_ocr.json` 是正常 `run_ocr` 的完整结果和配置/图像/识别模型哈希。八页均记录为 rapidocr、模型加载、非 demo。

`sample_matches.json` 保留每个样本外框与最终 OCR 输出框正面积相交的全部文本块与坐标。对每个标注剂量，在单个相交输出块中做原文子串匹配及项目归一化后子串匹配；不跨框拼接，不评判抽取结果的药味归属。正例中双列内 11 处剂量片段，精确 0/11，归一化 0/11。此数字用于诊断当前识别文本，不能充当剂量抽取或方剂表召回率。第 35 页开发样例基线另见 `output/small_columns_step1_dev/page35_full_ocr.json` 和 `page35_dose_match.json`。

`structure_check.json` 保存逐页数量、类别、哈希及尺寸、框合法性与包含、读序、样本 ID、页隔离、OCR 结果和命中覆盖；这些自动检查不证明每个字的识读、语义或标注框精度。复核时也应注意两条近邻大字和透印各仅一个反例。

## 复现

在仓库根目录运行，脚本会重写本任务输出目录中的同名结果；应保留固定标注和历史结果后再运行。正常 OCR 结果可能随模型、依赖、配置和环境变化。

```powershell
.\.venv\Scripts\python.exe tools/small_columns_step1_dev_baseline.py
.\.venv\Scripts\python.exe tools/small_columns_step1_check.py
.\.venv\Scripts\python.exe tools/small_columns_step1_candidates.py
.\.venv\Scripts\python.exe tools/small_columns_step1_holdout_baseline.py
.\.venv\Scripts\python.exe tools/small_columns_step1_holdout_check.py
```
