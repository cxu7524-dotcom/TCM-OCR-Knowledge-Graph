## 一、作品定位

面向**中医古籍与中药资源**的 **OCR 识别与知识图谱智能问答原型系统**。
要求形成可运行、可演示、可复现的四步链路：

```
上传古籍页 → 显示 OCR 与结构化结果 → 图谱可视化 → 可溯源问答
```

## 二、四步链路的技术要求（要点摘录）

| 步骤 | 要点 |
|---|---|
| ① 图像 → 文本 | 古籍竖排版面分析、列切分与阅读顺序；OCR 结果必须带 bbox；繁简 / 异体 / 通假归一化；方剂表与剂量结构还原 |
| ② 文本 → 结构化 | 定义中医药实体（药材 / 性味 / 归经 / 功效 / 主治 / 禁忌 / 方剂 / 剂量）与关系；规则 + 词典先跑通，本地 LLM 可选增强 |
| ③ 结构化 → 图谱 | 三元组构建、去重与冲突处理；支持「某症状常用药材」「某药禁忌」等查询；导出前端可视化 JSON |
| ④ 可溯源问答 | 稀疏 + 可选向量混合检索；答案强制引用原文证据；证据不足必须拒答 |

## 三、硬性约束（要点摘录）

1. **本地化优先**：核心推理全本地、零密钥、零公网调用；OCR 默认 CPU 可跑的 ONNX 方案；LLM 走本机 OpenAI 兼容 HTTP；后端可设 `none` 时用规则 + 桩降级演示。
2. **去重型依赖**：用 SQLite + JSON 替代 MySQL，取消装机门槛；保留「摘抄 + 坐标 + 批次幂等」设计思想。
3. **溯源是一等公民**：任何文本块、实体、三元组、答案证据都必须携带 `page_id / bbox / line_id / quote / source_hash`；字段定义集中一处，全链路不许丢字段；答案输出前逐条校验 `quote` 能在原文命中，否则转拒答。
4. **安全与合规**：每个页面常驻「仅供参考、非诊疗建议」；无证据时拒答并说明「原文未检索到依据」，禁止模型自由发挥；脱敏样本仅限赛事研发使用、不得外传；README 写明数据合规与保密义务。
5. **工程规范**：配置集中一处；建库 / 建索引 / 评测幂等可重跑；接口分层清晰、桩写明输入输出与 TODO；不写死绝对路径；保留中文注释与可复现说明。
6. **原型阶段不引入**需要额外安装的服务端组件（图数据库、搜索引擎、MySQL）；图谱用文件 + SQLite + 前端力导向图。

## 四、评测指标口径（五项，本阶段一律「待测」）

| 指标 | 口径 |
|---|---|
| CER 字符错误率 | 编辑距离(识别文本, 人工转写) / 人工转写字数，按页加权 |
| 字段级 P / R / F1 | 按 `(page_id, type, name, value)` 对齐，微平均 |
| 表格结构还原准确率 | 行列结构 + 单元格内容同时正确才算对 |
| 可溯源率 | 证据 `quote` 能回原文命中的条数 / 证据总条数 |
| 拒答率 | 无依据问题中正确拒答数 / 无依据问题总数 |

禁止编造实测数字，禁止把示例数据当评测结果。

## 五、本阶段范围
