# 面向中医古籍与中药资源的 OCR 识别与知识图谱智能问答原型系统
## 技术报告（初稿 v0.1）

> **【免责声明】本系统为赛事研发原型，所有内容仅供参考、不构成诊疗建议，不得用于临床决策。**
>
> **【数据声明】** 本报告全部实测数据来自两类非官方数据：① 本地合成的 24 页竖排繁体示意页；
> ② 公开古籍理解评测集 `bytedance-community/AncientDoc` 的医家类样本（59 页有标注）。
> **命题单位脱敏样本尚未到位**，本报告**不含任何命题单位样本数字，不是官方评测结果，不得用于评分申报**。
> 合成集、通用古籍集、医家类三组数据全程分列、不混算。

## 1 赛题理解与问题定义

### 1.1 面向对象与目标用户

系统面向**中医古籍（竖排繁体木刻/活字本）与中药资源文献**两类材料，目标用户是三类实际岗位：

- 古籍整理人员：需要把扫描页转成可检索文本，并保留版面位置以便核对；
- 知识库录入人员：需要把"药材—性味—归经—功效—主治—禁忌—方剂组成"结构化成可查询数据；
- 研究/教学人员：需要针对具体问题快速定位原文依据，而不是阅读整页。

### 1.2 四类具体难点与判定标准

| 难点 | 具体表现 | 判定标准 |
|---|---|---|
| 竖排与版面 | 从右向左、逐列自上而下；双页对开有书脊；界行、版框、页眉、版心并存 | 列切分与真实列数误差 ≤±2 列；跨列框率 <10%；书脊页正确分半 |
| 繁体与异体字 | 木刻字形与现代印刷体差异大；异体/通假字多（如「薑/姜」「兩/两」「欬/咳」） | 繁体页、含异体字页 CER **单列统计**，不混入总体 |
| 方剂表与剂量 | 药名—剂量—炮制三列结构，单元格短、字小、易漏 | 行列结构与单元格内容**同时正确**才算该表正确 |
| 可溯源 | 结论必须能定位到原文段落，模型不得臆造 | 每条证据 `quote` 必须能在原文块中命中；无依据必须拒答 |

### 1.3 与赛题评分的对应关系

按赛题建议权重：OCR 与版面还原 30 分、知识图谱与问答 35 分、原型完整度 20 分、
工程实现与可复现 10 分、展示与文档 5 分。本报告第 3 章对应 30 分项，第 4、5 章对应 35 分项，
第 2、7 章对应 20 分与 10 分项。

## 2 系统架构

### 2.1 四步链路

```
上传古籍页 → ① OCR 与版面还原 → ② 结构化抽取 → ③ 知识图谱 → ④ 可溯源问答
```

实现为单一 FastAPI 服务（`app/main.py`，8 个接口），前端为**零 CDN 依赖**的原生 HTML/JS
四步演示台（`app/web/index.html`），图谱用原生 Canvas 力导向图，不引入 D3/ECharts/Neo4j/Elasticsearch。

| 步骤 | 接口 | 负责模块 |
|---|---|---|
| ① 上传 | `POST /api/pages` | `ocr/pipeline.py` + `app/store.py` |
| ② 识别与结构化 | `GET /api/pages/{id}/ocr` | `ocr/*` + `extract/rules.py` |
| ③ 图谱 | `GET /api/graph` | `graph/build.py` + `graph/export.py` |
| ④ 问答 | `POST /api/qa` | `qa/retrieve.py` → `qa/generate.py` |

### 2.2 统一数据契约与溯源五元组

所有文本块、实体、三元组、答案证据**必须**携带五个字段，定义集中在 `app/schemas.py`，
全链路不允许丢字段：

```
page_id · bbox[x1,y1,x2,y2] · line_id · quote · source_hash
```

- `quote` 是原文摘抄，**一字不改**；繁简归一化只作用于比对，不回写原文；
- `source_hash` 由来源内容确定性生成，同页重复处理不膨胀；
- 问答输出前逐条校验 `quote` 能否在原文块中命中，**命中失败即转拒答**。

### 2.3 存储与可复现

用 SQLite + JSON 镜像替代数据库服务，`run_id` 由来源指纹确定性生成、唯一键不含 `run_id`，
因此**同页重复跑零膨胀**。评测脚本 `eval/run_all.py` 幂等可重跑，
GT 版本由六类标注文件内容 sha256 计算（如合成集 `514f99246f103a95`），报告必须注明。

### 2.4 本地化与零公网

- OCR 模型随包分发或放本地 `模型权重/`，运行时不下载；
- 大模型接口（若启用）只允许 `127.0.0.1` / `localhost`，`LlmConfig.is_local()` 硬拦截；
- 全库无 API Key 读取、无公有云 OCR 调用；
- **本报告所有数字均在 `TCM_LLM_BACKEND=none` 下产出，不含任何大模型参与。**

## 3 OCR 与版面还原（对应 30 分）

### 3.1 技术路线

`ocr/` 模块按「检测 → 识别 → 归一化 → 版面 → 表格」分层：

| 模块 | 职责 | 关键实现 |
|---|---|---|
| `recognize.py` | 识别适配层，可插拔 | rapidocr-onnxruntime（ONNX、纯 CPU）；支持 `TCM_OCR_REC_MODEL` 切换模型；`recognize_crop()` 供列内二次识别 |
| `vertical.py` | 竖排逐列 | 自适应二值化 → HSV 去朱丝栏/朱印 → 形态学去版框 → 垂直投影切列 → 列内投影切块 → 旋转 90° → 识别 → 坐标反变换；`split_spread()` 检测书脊分半页 |
| `layout.py` | 阅读顺序 | 列聚类、碎片合并、方向判定（竖长条框占比 + 列数 + 新增宽高比中位数等信号） |
| `normalize.py` | 繁简/异体 | `data/lexicon/异体字表.json` 单一字表，多字优先，通假只登记不改写 |
| `correct.py` | 字形纠错层 | 固定词、页眉正则、数字后剂量单位、药名词边界近形字；`TCM_OCR_CORRECT=0` 可整体回滚，每次纠错写 `ocr_corrections.jsonl` |
| `table.py` | 方剂表还原 | bbox 行列聚类 + 缺失单元格补识别 + 短文本整格二次识别 |

### 3.2 三次模型升级的实测对比

同一批 34 页真实古籍页（兵家/天文/传记，按书切分防泄漏）：

| 识别模型 | 文件大小 | CER 中位 | 覆盖率中位 |
|---|---|---|---|
| `ch_PP-OCRv3_rec`（包内简体） | 随包 | 0.4451 | 0.6451 |
| `chinese_cht_PP-OCRv3_rec_mobile`（繁体） | 11.15 MB | 0.2911 | 0.7643 |
| **`ch_PP-OCRv5_rec_mobile`** | 16.6 MB | **0.2287** | **0.8528** |

**结论：换模型是这一阶段收益最大的动作**，CER 降低 49%。本地包默认只有简体 rec 模型，
这是早期 CER 偏高的首要原因。

### 3.3 字形纠错层（合成集）

先诊断后改代码。错误块归因：识别错字 71.8%、检测漏框 23.1%、切分错位 5.1%，
其中**繁体字错误占 66.7%**，说明瓶颈在字形能力而非切图策略。据此走纠错层路线：

- 规则来源：固定词、页眉正则、数字后剂量单位、药名词边界近形字、术语表；
- 每条纠错写入 `ocr_corrections.jsonl`，可整体关闭；
- 修掉一处真实缺陷：早期允许词内替换，把「味甘平」误纠成「味甘草」导致证据失真，
  已加词边界约束。

合成集 CER **0.1911 → 0.0942**，纠错命中 111 块。

### 3.4 方剂表结构还原

口径为「行列结构与单元格内容**同时**正确才算该表正确」，同时单列单元格级正确率。
合成集实测：结构 **2/2** 正确、单元格级 **36/36 = 1.0000**、整表全对 **2/2（达标）**。

修复过程值得记录：此前整表 0/2，根因不是表格算法，而是**补格时 crop 边界过紧**——
实测同一格 `(580,692,644,730)` 能识别出字，边界只改 2px 就返回空字符串。
改为「多边界(0/4/8px) × 多缩放(2/3/4) 取最优」后，再补炮制闭集字形纠错（擎/璧→擘），
整表由 0/2 变为 2/2。

未达标原因如实记录：两张测试表各差 1 个炮制单元格（「擘」在低置信二次识别中输出「璧」）。
**未调整口径、未放宽判定**。

### 3.5 真实古籍页的真实水平（关键）

合成页字体规整、无污损、无透印、无印章，其 8.9% 的 CER **不能外推**。
用 60 张真实木刻页（含印章、透印、双页对开）实测：

| 阶段 | 配置 | 严格 CER 中位 | 覆盖率 |
|---|---|---|---|
| 初始 | 整页 + 简体 v3 | 0.8890 | 0.1920 |
| 阶段五 | v5 + auto 择优 | 0.2287（34 页通用集） | 0.8528 |

首次真实页测试的 CER 0.889、覆盖率 0.192，直接暴露了「合成集数字不可信」这一事实。
这也是本报告坚持三组数据分列的原因。

### 3.6 医家类 59 页全量结果（最有参考价值）

| 书 | 页数 | 严格 CER 中位 | 顺序无关 CER 中位 | 覆盖率 |
|---|---|---|---|---|
| 丹方彚编 | 21 | 0.9488 | 0.5842 | 0.6523 |
| 合併脉訣難經太素評林 | 16 | 0.9491 | 0.5713 | 0.6269 |
| **思濟堂方書** | **22** | **0.3251** | **0.2756** | **0.8322** |
| 合计 | 59 | 0.8485 | 0.4556 | 0.7195 |

严格 CER 偏高的三层原因（详见第 6 章）：**口径层**（13 页 GT 为简体转写、3 页 GT 超单页容量、
GT 字符顺序与页面阅读顺序不一致）、**顺序层**（14 页竖排曾被判为横排，已修但非主因）、
**识别层**（顺序无关 CER 仍 0.4556，密集小字与双行夹注混读）。

## 4 结构化抽取与知识图谱（对应 10 分）

### 4.1 实体与关系口径

| 类型 | 说明 | 示例 |
|---|---|---|
| 药材 | 药名（归一化字形） | 甘草、芍药、大枣 |
| 性味 | 味/性组合 | 味甘平 |
| 归经 | 经络归属 | 归肺经 |
| 功效 | 功能表述 | 轻身延年、温中下气 |
| 主治 | 主治病症 | 五脏六腑寒热邪气 |
| 禁忌 | 禁忌人群/配伍 | 反甘遂 |
| 剂量 | 数值 + 单位 + 炮制 | 二两炙 |

关系以 `(head, relation, tail)` 三元组表达，全部带证据引用，支持
「某症状常用药材」「某药禁忌」两类查询。

### 4.2 抽取实现与确定性修复

规则 + 词典抽取（`extract/rules.py`）先跑通，本地 LLM 留作后续增强。阶段五发现并修复一处
**可复现性缺陷**：功效词选择原用 `max(hits, key=len)`，`EFFECT_WORDS` 是 `set`，
等长命中时依赖 `PYTHONHASHSEED`，导致同一份 OCR 输出在不同进程抽出不同实体，
F1 在 0.5882 / 0.6471 之间随机跳。

修法：显式按「最长 → 文本中最先出现 → 字典序」排序取第一个（`_pick_main()`），
依据是古籍行文主次，**与 GT 无关**；三处调用点统一，并加 8 个确定性单测锁死「同输入 → 同输出」。

### 4.3 字段抽取实测

| 指标 | 值 | 阈值 | 判定 |
|---|---|---|---|
| 字段级 F1（合成集测试页） | **0.7879** | ≥0.80 | **接近未达标** |
| 其中：修正前（原值对齐） | 0.4314 | — | 口径对照 |
| 明细 | TP=33 / FP=17 / FN=19 | — | — |

**口径修正说明（重要）**：GT 的 `name` 保留繁体（如「芍藥」）、`value` 归一化为简体（「芍药」），
而早期对齐键 `(page_id, type, name, value)` 直接比对原值，`name` 未归一化，
导致抽对了也算错。现统一为 `app/schemas.py:align_norm()` + `entity_align_key()` 唯一实现，
GT 与预测**对称**归一化（去空白标点 + 异体/繁简映射），GT 原文与 `quote` 一字未改。
F1 由 0.4314 升至 0.7879（口径修正 0.4314→0.6471，表格剂量列与归经修复 0.6471→0.7879），
**差异分别来自字形等价判定与抽取规则修正，不是模型能力提升**，报告双列披露。

剩余误差来源：OCR 漏字导致主治短语缺字、部分 GT 功效实体是机器生成的截断词、
少量繁体字形差异不做全局回写。

## 5 可溯源问答（对应 25 分）

### 5.1 检索与生成

- 检索：字面 + bigram 三层打分（标签命中 / 完整命中 / 局部命中）的稀疏通道，
  可选向量通道（默认关闭，`qa/index.py` 的 hash 后端为占位实现，**非语义向量**）；
- 生成：当前为**抽取式原文摘录**，只列命中证据，不做推断、不改写原文；
- 边界：个人诊疗、疗效、剂量建议类问题按输出边界直接拒答；全站常驻
  「仅供参考、非诊疗建议」。

### 5.2 证据强约束

`qa/generate.py:verify_evidences()` 是硬闸门：逐条校验契约字段完整性 +
`quote` 能否在原文 `Block.text` 中命中，未通过的证据直接丢弃并触发拒答。
该逻辑**在任何阶段都未放宽**。

### 5.3 实测与口径局限

| 指标 | 值 | 阈值 | 判定 |
|---|---|---|---|
| 问答可溯源率 | 1.0000（106/106） | ≥0.90 | 达标（**构造性口径**） |
| 无依据正确拒答率 | 1.0000（35/35） | ≥0.85 | 达标 |
| 应答题正确作答率（配对） | 0.9062（29/32） | 无 | 配对观察 |

**必须说明的两点局限**：

1. 可溯源率接近闭环自校验——系统只输出通过 `quote` 校验的证据，未通过的已转拒答，
   因此该指标衡量的是「输出证据能否回原文」，**不等于「答案是否回答了问题」**；
2. 拒答率只统计无依据问题，会掩盖「应答题被误拒」，因此必须与应答题正确作答率配对解读。

## 6 评测方法与结果（对应「关键指标实测可验证」）

### 6.1 指标口径

| 指标 | 口径 |
|---|---|
| CER | 编辑距离 / GT 字数，按页加权；繁体页、含异体字页单列 |
| 覆盖率 | 预测中能在 GT 内匹配的字数 / 预测长度（多重集交集） |
| 插入率 | (预测字数 − 匹配字数) / GT 字数 |
| 顺序无关 CER | 两侧字符各自排序后再算编辑距离，**仅作诊断**，不参与判定 |
| 字段 F1 | 按 `(page_id, type, name, value)` 归一化对齐，微平均 |
| 表格结构 | 行列结构序列 + 单元格文本序列都相同才算该表正确 |
| 可溯源率 / 拒答率 | 见 5.3 |

`is_demo=True` 或缺溯源字段的记录由 `clean_records()` 与各 `compute_*` **双重排除**；
无有效样本时返回「待测」而非 0 分。

### 6.2 三组数据分列

| 数据集 | 页数 | 严格 CER 中位 | 顺序无关 CER 中位 | 覆盖率 | 插入率 | 用途 |
|---|---|---|---|---|---|---|
| 合成示意集（测试页） | 7/24 | 0.0942 | — | ~1.0 | — | 工程自测，证明链路可跑 |
| 通用古籍验证集 | 34 | 0.2287 | — | 0.8528 | — | 竖排 + 繁体模型效果 |
| 医家类全量 | 59 | 0.8485 | 0.4556 | 0.7195 | 0.2086 | 真实难度，含口径污染 |
| 医家类正常页 | 43 | 0.5777 | 0.3793 | 0.7724 | 0.2086 | **最能代表真实水平** |
| **思濟堂方書干净子集** | **22** | **0.3251** | **0.2756** | **0.8322** | 0.1638 | **代表性数字** |

### 6.3 口径污染声明（本报告最重要的方法论说明）

医家类 59 页严格 CER 0.8485 中，有相当部分**与识别能力无关**：

1. **13 页 GT 为简体转写**，模型输出繁体，逐字皆错 → 该组 CER 中位 0.9532，
   而繁体 GT 页仅 0.6009。这属于数据集繁简混杂，不是识别错误。
2. **3 页 GT 远超单页容量**（如 3131 字），含图注、多段、旁批，单页识别不可能覆盖 → CER 有下限。
3. **GT 字符顺序与页面阅读顺序不一致**：14 页目录/索引/图注页的 GT 转写顺序既非行序也非列序，
   任何几何阅读顺序都无法对齐。阶段七修好方向判定后严格 CER 纹丝不动（0.8485 → 0.8485），
   正是这个原因。
4. **多余文字归因**（12 页抽样）：插入文字中 **60% 是背面透印/同一段重复读出、
   34% 是版心牌记图注手写序、仅 6% 是真错字**。

**因此：严格 CER 必须与覆盖率、插入率、顺序无关 CER 一起读，禁止单独引用。**
主判据采用「顺序无关 CER + 覆盖率」，严格 CER 保留为参考列、不隐藏。

### 6.4 未达标项汇总（如实）

| 指标 | 实测 | 阈值 | 判定 | 原因 |
|---|---|---|---|---|
| 字段 F1 | 0.7879 | ≥0.80 | 差 0.012 | OCR 漏字、GT 截断词、GT 主治粒度不统一 |
| 方剂表整表正确率 | **2/2 = 1.0000** | ≥0.80 | **达标** | 已修：补格边界重试 + 炮制字形纠错 |
| 医家类严格 CER | 0.8485 | 无 | 参考 | 口径污染为主，识别层次之 |
| 医家类顺序无关 CER | 0.4556 | — | 需专项 | 密集小字、双行夹注、生僻药材名 |

**未通过改写 GT、只归一化预测、放宽阈值或剔除失败页来提分。**

## 7 工程实现与可复现（对应 10 分）

- **一键启动**：`pip install -r requirements.txt` → `python app/main.py`（或双击 `启动操作台.bat`），
  不需要数据库服务、不需要密钥、不需要 GPU、不联网；
- **幂等**：建库、建索引、评测全部可重复执行，同页重复跑零膨胀；
- **单测**：38+ 用例，覆盖版面方向、坐标反变换、书脊切分、跨列框抑制、归一化、指标口径、
  抽取确定性；
- **可追溯**：每个指标值可追到 `data/reports/` 下对应 JSON 与 GT 版本哈希；
- **依赖分层**：core 必装（fastapi/uvicorn/multipart），ocr/llm/vector 为可选注释区，
  缺失时自动降级并显式标注，绝不伪造结果。

## 9 局限与后续工作

### 9.1 已知局限

1. **GT 口径是当前最大瓶颈**：外部数据集的简繁混杂、超长转写、顺序不一致，
   决定了严格 CER 的天花板，已不是算法能解决；
2. **识别层仍有一半字符错/漏**（顺序无关 CER 0.4556）：密集小字、双行夹注混读、
   生僻药材名与炮制字字形能力不足；
3. **目录/索引/图注页**的非正文文字被当作正文读入（插入率 0.2086）；
4. **短标题列被过滤**：`MIN_COL_RATIO=0.12` 会丢掉「叙記」这类单行短列；
5. **列数准确率统计意义不足**：修复抽样键碰撞后仅剩 1 页有效样本。

### 9.2 后续优先级

| 优先 | 事项 | 前置条件 |
|---|---|---|
| 1 | 技术报告定稿 / 汇报 PPT / 演示视频 | 本报告定稿 |
| 2 | 命题单位样本接收与双人标注（Kappa ≥0.80、抽检 ≥20%） | 样本与授权到位（**未到位**） |
| 3 | GT 顺序人工重标，或单独立项用「集合级」口径 | 不能悄悄改 CER 定义 |
| 4 | 医书专项：双行夹注分离、生僻药材字纠错表扩充 | 第 3 项有结论后 |
| 5 | 本地 LLM（Ollama/vLLM）接入抽取与生成 | 顺序无关 CER <0.35、F1 稳定、本机模型可用 |
| 6 | 模型微调 | 真实标注页 ≥100、CER 已到瓶颈、有 GPU（**三条均未满足**） |

### 9.3 结论

本系统完成了「图像 → 文本 → 结构化 → 图谱 → 可溯源问答」的端到端可运行原型，
在版面干净、繁简一致的古籍页上（思濟堂 22 页）达到 **CER 0.3251 / 顺序无关 0.2756 / 覆盖率 0.8322**；
在含目录、插图、双行夹注的复杂医书页上仍有明显差距（顺序无关 CER 0.4556）。
问答链路的可溯源与拒答机制为**构造性达标**，需与应答题正确作答率 0.9062 配对解读。

**本报告所有数字均可用附录命令复现，未使用任何命题单位样本，不构成官方评测结论。**
