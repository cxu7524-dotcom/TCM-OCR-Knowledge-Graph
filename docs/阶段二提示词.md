## 3. 赛题硬约束（自包含，执行时以本节为准）

- **评分权重（100 分）**：OCR 与版面还原 30（字符/字段识别 15、方剂表结构与剂量 10、异体字 5）；知识图谱与问答 35（抽取与图谱覆盖 10、问答可溯源率 15、无依据正确拒答 10）；原型完整度 20（端到端可演示 12、免责声明与边界处理 8）；工程实现与可复现 10；展示与文档 5。
- **参考指标阈值**：关键实体字段抽取 **F1 ≥ 0.80**；方剂表结构还原在测试页达到可用水平；问答**可溯源率 ≥ 90%**；无依据问题**正确拒答率 ≥ 85%**。
- **异体字 / 繁体必须单列评测**，不能混在总体 CER 里一笔带过。
- 评审四关注点：方案匹配度与创新性；工程完整度与**关键指标实测可验证**；本地化部署与数据安全合规（不依赖公有云在线推理）；成果转化与落地对接。
- 提交物（阶段三交付，本阶段只预留结构）：技术报告 10–30 页 PDF、汇报 PPT、≤5 分钟且 ≥1920×1080 的 mp4/avi/wmv 演示视频（含原理创新点、系统结构、功能演示三部分）、带注释可复现原型工程与评测脚本。
- 合规：命题单位脱敏样本仅限赛事研发使用，赛后按约定删除/归还；不得外传、不得上传任何外部服务；允许使用**公开中医古籍数字化文本、中药学教材结构**补充。

## 6. 执行顺序

### A. 评测基建先行（性价比最高，先变现 25 分）

1. 实现 `eval/metrics.py` 的五个 `compute_*`：`compute_cer`（标准库编辑距离，按页加权）、`compute_field_f1`（按 `(page_id,type,name,value)` 微平均 P/R/F1）、`compute_table_structure`（行列+单元格全对才算对）、`compute_traceability`（`quote` 回原文命中数 / 证据总数）、`compute_refusal`（无依据问题中正确拒答数 / 总数）。全部拒绝 `is_demo=True` 的记录；输入缺失时返回 `status="待测"` 而不是 0 分。
2. 重写 `eval/run_all.py`：从 `data/annotation/` 读 GT、从 `data/reports/` 或 SQLite 读预测与问答日志，逐项算分，**按第 3 节阈值标注「达标 / 未达标」**（未达标如实写，不许美化），输出 `data/reports/正式评测报告.md` + `评测明细.json`，幂等可重跑。保留 `评测报告骨架.md` 的自检章节，但明确标注「示例数据、非指标」。
3. 建 `eval/dataset.py`：GT 加载 / 校验 / 对齐工具，按 `page_id` 切分训练与测试页，输出版本哈希（报告须注明 GT 版本）。
4. 建 `data/annotation/` 的六类 GT 文件生成与校验脚本（格式严格对齐现有 `README.md` 规范）：`ocr_transcription.jsonl`、`entities.jsonl`、`relations.jsonl`、`tables.jsonl`、`qa_log_gold.jsonl`、`qa_no_evidence.jsonl`。

### B. 数据基线（与 A 并行，不依赖命题单位）

1. 建 `tools/make_synthetic_pages.py`：用**公开中医古籍数字化文本 / 中药学教材结构**的短句，生成 20–30 页可复现的竖排繁体示意页（含三类：竖排繁体正文、方剂/剂量表、含异体字与通假字页），同步输出逐页 GT 与 bbox 元数据。优先用 Pillow 渲染；**若离线装不上 Pillow**，退化为「直接输出带 bbox 的页面 JSON + 不生成影像」，并在报告注明该限制，不得声称做了图像识别。
2. 无依据问题集 ≥ 30 条，覆盖三类：原文完全未出现、需个人诊疗建议、疗效/剂量类越界；每条带期望 `refused=true` 与理由。
3. 若命题单位样本到位：按 `data/samples/README.md` 登记，单独跑一轮并在报告中**与合成集分列**，不混算。
4. 标注一致性：写出 `data/annotation/标注指南.md`（双人独立标注、第三人裁决、Kappa/抽检比例、GT 版本号与变更日志）。合成集由脚本生成 GT 时须说明「机器生成 GT，人工抽检 N 页」及抽检结果。

### C. 本地 OCR 真接入（30 分主战场）

1. **先查 API 再写代码**：安装 `rapidocr-onnxruntime`（`pip install rapidocr-onnxruntime`，连带 onnxruntime/Pillow/numpy）；阅读已安装包内的 `__init__.py` / README 确认调用签名与返回结构，**不要凭记忆猜 API**。若环境无法安装，改用本机已有的其他离线 OCR（如 `tesseract` 的 `chi_tra`），并在 `engine` 与报告中如实登记；仍不可用则保留 stub 并把 CER 标记为「待测」，不许用示例文本冒充识别结果。
2. 实现 `ocr/recognize.py:RapidOcrAdapter.infer()` 与 `recognize()`：图像 → `(text, conf, box)` 列表 → `Block`，映射 `box→bbox`、`score→conf`，补齐 `page_id / line_id / quote / source_hash`，`model_loaded=True`、`is_demo=False`。同步修掉 `get_adapter()` 里「包已安装仍强制降级」的分支。
3. 竖排策略写进 `ocr/layout.py`：按 bbox 做列聚类（x 投影/间隙）→ 从右向左定 `col_id` → 列内按 y 排 `reading_order` → 旋转或逐列送识别 → 坐标映射回原图；处理小字夹注、页眉页脚、跨列续句。`detect_direction()` 改为基于 bbox 宽高比与列数的可解释判别，附单元测试。
4. `ocr/normalize.py`：把演示小表扩成可维护的 `data/lexicon/异体字表.json`（繁简 / 异体 / 通假，含来源与置信等级），提供命中率统计；**繁体识别准确率与异体字归一化命中率在报告中单列**（赛题 5 分）。
5. `ocr/table.py`：基于 bbox 行列聚类还原方剂表与剂量，输出结构化单元格（药味 / 剂量 / 单位 / 炮制），保留 `quote` 与 bbox；给出「可用水平」的判定口径（如单元格内容正确率 + 行列结构正确率 jointly）。
6. `ocr/pipeline.py`：接真实宽高（不再硬编码 720×1000）、接低置信过滤与人工复核队列（阈值 `TCM_OCR_MIN_CONF`，当前 0.50）、失败时降级但**必须标注**。

### D. 抽取与问答链路升级（保住可溯源与拒答）

1. `extract/rules.py` + `graph/build.py`：在合成页 GT 上跑通并计算字段 F1；补齐跨行主语归属的确定性规则或明确降级策略，冲突消解写进 `trace`。
2. `qa/retrieve.py` / `qa/generate.py` / `qa/refuse.py`：用 `qa_no_evidence.jsonl` 与 `qa_log_gold.jsonl` 跑批，输出问答日志到 `data/reports/qa_log.jsonl`（每条含 `evidences / refused / refuse_reason / trace`）。**`verify_evidences()` 的 quote 回原文校验不许放宽**；无依据、越界、诊疗建议类一律拒答。
3. `eval/audit.py`：从真实问答日志做反向溯源审计，统计「完全 / 部分 / 未溯」，与 `compute_traceability` 交叉核对。
4. 前端 `app/web/index.html`：把真实 OCR 的 bbox 叠加显示、点证据卡片高亮对应原文块；保留常驻免责声明；真实数据到位后移除「示例数据 / 模型未接入」横幅，改为按 `is_demo` 动态显示（示例页仍要标）。

### E. 文档与提交

1. 同步 `README.md`：新增「阶段二实测」章节，表格列出五项指标的**值 / 阈值 / 达标情况 / GT 版本 / 数据来源（合成集或命题样本）**；把「当前阶段只搭框架」改为准确描述；更新快速开始里的可选依赖安装命令。
2. `requirements.txt`：把实际启用且验证通过的依赖从注释区移入安装区，注明版本与 CPU 可跑；未装上的仍留注释并说明降级。
3. `docs/改造说明.md` 追加「阶段二」章节；新建 `docs/交付物清单.md`（技术报告 / PPT / 视频 / 复现脚本的占位与验收口径）。

## 7. 验收标准（本阶段完成的定义）

1. `python eval/run_all.py` 可重跑，产出 `data/reports/正式评测报告.md`；五项指标中至少 **可溯源率、拒答率、字段 F1** 三项为脚本算出的真实数值（非「待测」、非手写），并对照第 3 节阈值标注达标/未达标。
