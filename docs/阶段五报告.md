## 2. P0 回归诊断（块级证据）

### 2.1 对照实验：OCR 输出逐字节一致

```
TCM_OCR_VERTICAL_SPLIT=0 python eval/run_all.py --refresh   → F1 0.5882  CER 0.0890
TCM_OCR_VERTICAL_SPLIT=1 python eval/run_all.py --refresh   → F1 0.6471  CER 0.0890
两份 ocr_predictions.jsonl  sha256 = c80b5161f323（完全相同，240 条）
两份 extraction_predictions.jsonl 条数相同（166），内容不同（7 条差异）
```

→ 逐列切分没有改变任何 OCR 输出（合成页是横排版式，`is_vertical_page` 为假，逐列路径根本没跑），
所以「块结构变化导致 F1 下降」这个解释不成立。

### 2.2 差异定位：只差 7 条「功效」实体

按 `(page_id, type, name, value)` 归一化对齐后逐条比较，A/B 两份预测**只差 7 条**，且全部是功效：

| 页 | 修前（v0 抽到） | 修后（v1 抽到） | GT |
|---|---|---|---|
| p0001/p0002/p0003/p0004/p0005/p0007/p0008 | 温中下气 | 轻身延年 | 轻身延年 |

按 type 分组统计（全 24 页，相对 GT）：仅 `功效` 一项变化 `TP=1/FP=18/FN=15 → TP=8/FP=11/FN=8`，
其余类型（药材/性味/主治/剂量/禁忌/归经）**逐项完全相同**。

### 2.3 根因：set 迭代顺序 + 等长并列

原文行是「久服輕身延年溫中下氣」，`EFFECT_WORDS` 里「轻身延年」和「温中下气」都是 4 字。
`extract/rules.py` 原来写的是：

```python
eff_hits = [w for w in EFFECT_WORDS if w in text]   # EFFECT_WORDS 是 set
add(max(eff_hits, key=len), "功效")                  # 等长时谁先迭代到就选谁
```

`EFFECT_WORDS` 是 `set`，Python 字符串哈希逐进程随机（`PYTHONHASHSEED`），
于是同一份 OCR 输出在不同进程里抽出不同实体，F1 在 0.5882 / 0.6471 之间随机跳。
复现证据（同一份 `ocr_predictions.jsonl`，只换哈希种子）：

```
PYTHONHASHSEED=0     ents=166 hash=fb30a6ec0a8f
PYTHONHASHSEED=1     ents=166 hash=6039d1ef833a
PYTHONHASHSEED=2     ents=166 hash=6321cfd95e2c
PYTHONHASHSEED=12345 ents=166 hash=fb30a6ec0a8f   ← 与 seed=0 相同，说明是顺序随机而非逻辑不同
```

### 2.4 修法（不放宽任何口径）

新增 `extract/rules.py:_pick_main(text, words)`：显式按 **最长 → 文本中最先出现 → 字典序** 排序取第一个。
「最先出现」的依据是古籍行文主次（先述者为主功效），**与 GT 无关**；三处调用点统一：
`extract_entities` 的功效、性味最长命中、`candidate_triples` 的功效。

修复后跨种子稳定：

```
PYTHONHASHSEED=0/2/777 → ents=166 triples=106 hash=e94e6f26ea97（三次完全一致）
```

护栏：新增 `tests/test_extract_determinism.py`（8 个用例）锁死「同输入 → 同输出」。
